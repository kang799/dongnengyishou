目标：让游客退出后再次进入登录页时，选择“继续游客”可以稳定回到原游客账号；如果历史 token 已经被旧版本全局注销，也能给出可恢复路径，避免用户只能反复新建账号。

实施计划：

1. 先修正退出行为
- 在退出前读取当前 profile，确认是否为游客。
- 游客退出只做本地退出，不调用会让后台会话失效的全局注销。
- 普通邮箱账号仍使用正常注销，避免影响正式账号安全。

2. 改造游客会话缓存
- 缓存游客 session 时增加保存当前 Lovable Cloud auth storage 的 key 信息，退出游客时只清理当前登录态，不删除游客恢复缓存。
- 增加“刷新并保存最新 token”的工具函数：游客登录、游客恢复成功、页面已有游客 session 时都更新缓存，避免 token 轮换后下次恢复失败。

3. 修复“继续游客”的恢复逻辑
- 不再只用旧 access_token + refresh_token 直接 setSession。
- 优先使用 refresh token 刷新出新 session，再保存新 token 并进入 `/pet`。
- 如果刷新失败，再清除无效缓存并提示“游客身份已失效，请新建账号”。这样旧版本已被全局注销的游客会被明确清理，新版本创建的游客之后可正常恢复。

4. 补一层防误触与状态处理
- 游客提示弹窗关闭时不自动删除缓存，只有用户明确点“新建账号”才清除。
- “游客入山”如果检测到旧游客缓存，先弹出双选项，让用户选择继续旧游客或新建游客。

验证方式：
- 检查代码里不再对游客触发全局 `/logout`。
- 验证流程：游客入山 → 归隐 → 进入登录页 → 选择继续游客 → 回到同一游客数据。
- 验证普通账号：邮箱登录 → 归隐 → 会话正常注销。
