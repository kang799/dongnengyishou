我建议不要再继续微调现在的阈值。原因很明确：只拍上半身时，摄像头看不到膝盖和髋部，AI 没法真正判断“膝盖弯曲角度”，只能从肩膀/头部的上下移动推断深蹲；如果没有明确校准，很容易 10 个都不计数。

本次要改成一个更可靠的方案：

## 1. 深蹲改为“校准式上半身计数”

进入深蹲训练后，不直接开始计数，而是分两步校准：

1. 站直 2 秒，记录“站立高度”
2. 做一次标准下蹲并保持片刻，记录“下蹲高度”

之后计数不再依赖固定阈值，而是使用用户自己的站立/下蹲高度区间：

```text
站立高度 = 0%
下蹲高度 = 100%
下降超过约 65% -> 进入下蹲状态
回升到约 25% 以内 -> 记 1 次
```

这样不同身高、摄像头角度、只拍上半身、桌面/手机距离不同，都能适配。

## 2. 加实时反馈，不再让用户“猜为什么没计数”

训练画面增加状态提示：

- “请站直，正在校准”
- “请下蹲一次，记录最低点”
- “校准完成，可以开始”
- “动作太小，再蹲低一点”
- “未检测到肩部，请把上半身放进画面”
- “已进入下蹲 / 回到站立后计数”

同时显示一个动作进度条，让用户看到系统有没有识别到身体在下降，而不是只看计数是否变化。

## 3. 深蹲优先使用更稳定的关键点

上半身模式将综合使用：

- 双肩中心点高度
- 鼻子/头部高度作为备用
- 肩宽变化只作为辅助，不再作为主要判断
- 连续多帧稳定后才切换“站立/下蹲”状态

如果肩膀短暂丢失，不立刻清空状态，而是允许短时间容错，避免动作过程中掉帧导致不计数。

## 4. 摄像头卡退改为稳定优先

当前日志显示 MediaPipe 一直在启用 WebGL/GPU，这类模式在一些浏览器和设备上容易卡顿或掉帧。为了稳定，训练页改为：

- 默认使用 CPU 模式，不再优先 GPU
- 降低识别频率到约 8–10 FPS
- 检测循环加“忙碌锁”，上一帧没处理完不处理下一帧
- 页面离开/收功时彻底释放摄像头和动画循环
- 不在进入页面时立即预热 GPU 模型，改为点击启动后加载

目标是牺牲一点点识别速度，换稳定不闪退。

## 5. 修行页交互调整

深蹲训练按钮流程改为：

```text
启动修行
-> 摄像头打开
-> 站直校准
-> 下蹲校准
-> 开始正式计数
-> 收功保存数据
```

俯卧撑和仰卧起坐保持原逻辑，不强制走这个校准流程。

## 6. 如果这版仍然不准，最终方案

如果用户的摄像头只能拍到胸口以上，纯视觉深蹲依然会有物理限制。最终可靠方案是增加“手机体感计数”：让用户拿着手机做深蹲，用手机加速度/陀螺仪计数。这比只看上半身摄像头更可靠。

但本次先把摄像头方案做到可校准、可反馈、稳定优先。
